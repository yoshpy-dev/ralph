## Objective

Run the trial of FR-12 on this repository: two feature orgs at the same
time, started from one approved split plan, each fixing one small open
tech-debt item and opening one PR, with this session promoted to the
director and the user as the human who approves and decides merges.
Measure, from the ledger, the human's interventions (count and latency),
the approval wait of each feature plan, the total cost, and whether
stopping and restarting succeeded. Review the defaults of `max_orgs`,
`max_total_seats`, `ack_minutes`, and `resolve_minutes` with those
numbers, and record the trial in the evidence, the spec, and the
tech-debt register.

The user decided on 2026-10-20 (all four recommended options):

- measure from the ledger (the inbox, the manifest, the director's
  records); take the cost from each CLI's usage records; the human only
  answers as usual
- two small tech-debt fixes, two orgs (leader, implementer, reviewer,
  all claude) in an isolated herdr server under `/tmp`, this session as
  the director
- the human first adds the required status check `verify` and "Require
  branches to be up to date before merging" to the main ruleset, with no
  bypass for the account the director uses; then `ralph org merge` and
  `auto_merge` are tried
- the human approves the feature plans (`ralph org approve`) and decides
  the merges; the director raises the approval questions to the human

## Scope

- The trial's setup outside the repository: a fresh clone, a `ralph`
  binary built from main, an `osascript` shim, an isolated headless
  herdr server (S1)
- The trial itself, run by this session as the director with the
  `/director` skill: the split plan, two `ralph org start --plan`, the
  inbox, the human's approvals, the stop-and-restart checks, the PRs,
  the merges (S2, S3)
- Aggregating the numbers from the ledger and the seats' usage records,
  and writing them into a committed evidence file (S4)
- Reviewing the four defaults with the numbers and recording the result
  in the spec (FR-12 and Open questions) and the tech-debt register (S5)
- Cleaning up everything the trial started (S6)

## Non-goals

  (S5). A finding that blocks the trial stops it, and the trial's record
  says where it stopped; the fix is a separate plan
- codex seats, a codex director, and the headless director
  (`ralph org director start`): the user chose claude seats and the
  promoted director
- Changing the repository's ruleset (the human does it) or GitHub
  settings of any kind
- A real OS notification: the human path runs against a logging shim
  (D3)
- A reusable metrics command. The aggregation is a set of `jq` commands
  written into the evidence so it can be run again by hand
- The "talk to the director from a phone" open question
- Changing any default without a reason the trial's numbers give (D7)

## Design decisions

Critical forks: None asked. The user's four decisions above settle the
forks of measurement, place, ruleset, and approver; the rest are below.

- D1 (place): run from a fresh clone at `/tmp/ot/ralph`
  (`git clone ssh://git@github.com/yoshpy-dev/ralph.git`), not from the
  main checkout. The clone's ledger, feature worktrees, and claude trust
  entries stay away from the main checkout and its task worktrees (this
  plan's own worktree among them). The PRs still go to GitHub
- D2 (isolation): one headless herdr server started with `env -i`, the
  real HOME (claude needs the keychain), `SHELL=/bin/bash`,
  `PATH=/tmp/ot/bin:<the tools' dirs>`, and `XDG_CONFIG_HOME`,
  `XDG_STATE_HOME`, `HERDR_SOCKET_PATH` under `/tmp/ot/`. Every
  `ralph` and `herdr` command of the trial runs with the same
  `HERDR_SOCKET_PATH` and the same PATH. The binary is built from the
  clone's HEAD (main) with `go build -o /tmp/ot/bin/ralph ./cmd/ralph`.
  The server's environment also holds `GOFLAGS=-timeout=30m`, which
  reaches the leaders' gates (`gateScriptEnv` in
  `internal/org/gate_run.go` strips only `RALPH_VERIFY_*` and
  `HARNESS_VERIFY_*`): `go test ./...` in
  `packs/languages/golang/verify.sh` has no `-timeout`, and under load
  `internal/org` has passed the 10-minute default (tech-debt row 307)
- D3 (notifications): `/tmp/ot/bin/osascript` is a shim that appends its
  arguments to `/tmp/ot/osascript.log` and exits 0, so the human path
  (`ralph org escalate` without a watch, the deadlines) never shows a
  real notification. What the path sent is counted from the ledger's
  `escalations.jsonl` and the shim's log; the director tells the user
  in chat
- D4 (models): leader `opus` (`ralph org start --model opus`), and the
  leader is told in the split plan's feature text to spawn the
  implementer with `opus` and the reviewer with `sonnet`
  (`.claude/rules/ralph/model-routing.md`). Seats run with the default
  permission envelope (`autonomous`)
- D5 (measurement): the numbers and where each comes from
  - interventions: every time the director needs the human (approving
    the split plan, approving a feature plan, asking for a merge,
    turning `auto_merge` on, answering a QUESTION or BLOCKED, a
    consent dialog), the director logs the UTC time it asked and the
    time the answer arrived in `interventions.log` in this session's
    scratchpad (not under `/tmp/ot/`, which S6 removes); latency is the
    difference. The ledger events that each answer causes
    (`plan_approved`, `pr_merged`, `resolved`) are listed next to it.
    The time the human spent thinking is not separable from the latency
    and is not claimed
  - approval wait: for each feature plan, the inbox item's `created`
    time to the `plan_approved` event's time
  - the director's handling, per inbox item: `created` to `acked`, and
    `created` to `resolved` (`inbox.jsonl`), and every `notified`
    event with its reason (`inbox_ack_deadline`,
    `inbox_resolve_deadline`, `inbox_no_watch`, `inbox_manual_notify`,
    ...). These, not the approval wait, are what `ack_minutes` and
    `resolve_minutes` act on (an acked item has no ack deadline)
  - cost: for each seat, the claude session record under
    `~/.claude/projects/` (input, output, cache-read and cache-write
    tokens summed by model), turned into an estimate with the list
    prices of the day, written with the prices used. The director's own
    cost is not separable from this session and is left out (said so)
  - stop and restart: D6
- D6 (stop and restart), in two parts. The first is the one FR-12's
  "停止と再開" names (it pairs with FR-2's `ralph org stop` and the
  safety invariant): stop one feature org while it waits for the
  human's plan approval (`ralph org stop --org-id <org>`, all its
  seats), then start it again for the same feature
  (`ralph org start --plan <split> --feature <slug>`, which reuses the
  feature's worktree). Recorded: whether stop stopped every seat and
  closed its panes, whether the new start was accepted, whether the new
  leader began the template from the beginning (a new feature plan and a
  new approval QUESTION; tech-debt row 233 says the template has no
  resume path), what was lost (the old plan, the old QUESTION, which the
  director resolves with a note), and the extra intervention it cost.
  The other org keeps running. The second part checks the watch: at a
  moment when no TASK is due (both orgs waiting for the human's plan
  approval, or both implementers working), the director asks the human
  to stop the watch
  (`ralph org watch --all --stop`). Expected: the director's wait ends
  with exit 4, and a TASK sent with `ralph org send --dry-run` to a
  running seat is refused by the watch gate, which runs before the
  dry-run branch and records nothing (`Send` in `internal/org/verbs.go`).
  The human then says to restart it (`ralph org watch --all --detach`),
  and the next wait accepts work again. Recorded: the times, the exit
  codes, and whether each step went as expected. The leaders' own
  refusals in that window, if any, are recorded too
- D7 (defaults): a default changes only when the trial's numbers give a
  reason. `ack_minutes` is judged by the items' `created` to `acked`
  times and the `inbox_ack_deadline` notifications; `resolve_minutes` by
  the `created` to `resolved` times and the `inbox_resolve_deadline`
  notifications (for example, items the director had acked and was
  working on with the human that still reached the human path at the
  resolve deadline). The plan approval wait is reported but does not by
  itself move a deadline: once the director acks an item, the human's
  approval latency only counts against `resolve_minutes`. With two orgs
  and six seats, `max_orgs` and `max_total_seats` are not reached, so
  the trial gives no reason to change them; S5 says so instead of
  guessing
- D8 (merges): the first PR that is `ready` is merged with
  `ralph org merge` when the human asks. The other PR is then `rebase`;
  with the human's go, `auto_merge = true` is written to the clone's
  `ralph.toml` (excluded through the clone's `.git/info/exclude`), and
  the director regates and merges it as the `/director` skill says
  (before writing it, S1 checks with a scratch file that a `ralph.toml`
  holding only `[org.director]` with `auto_merge = true` loads and that
  `ralph org director status --config <file>` shows `auto_merge: true`). If
  the ruleset is not fixed by then, `ralph org merge` refuses; the human
  merges in GitHub and the record says so (row 297 stays open)
- D9 (feature tasks): the two features are fixes of open tech-debt rows
  whose files are disjoint and outside what the trial and this plan
  edit. They do not edit `docs/tech-debt/README.md`; this plan's PR
  marks their parts resolved (S5), so the two feature PRs cannot
  conflict there. Chosen from six candidates a research subagent
  proposed (both one-function escaping fixes of about the same size, in
  different packages, so their costs compare):
  - `report-escape` (Type `fix`, Reserve `internal/org/report.go`,
    `internal/org/report_test.go`): part (a) of row 216. The event
    timeline of `ralph org report` writes each event's Details into a
    Markdown table row as it is (`internal/org/report.go:179`), so a
    `|` in Details breaks the row; escape it, with a test whose row
    keeps four cells
  - `doctor-escape` (Type `fix`, Reserve
    `internal/cli/doctor_merge_guarantee.go`,
    `internal/cli/doctor_merge_guarantee_test.go`): part (h) of row 245.
    `mergeGuaranteeResult` sets the Detail of doctor's `Merge guarantee`
    check without escaping its local parts
    (`internal/cli/doctor_merge_guarantee.go:90`); pass it through
    `org.PrintableInboxText` once, with a test that a control character
    in the cache path does not reach the Detail raw
  Slugs stay at 13 characters, so `<org_id>_implementer` is 25 of
  herdr's 32
- D11 (precursor): `tests/test-secret-scan.sh` writes to two fixed
  `/tmp` paths (tech-debt row 170), and two copies running at once fail
  each other. Both leaders' gates run it (`run-test.sh` runs every
  `tests/test-*.sh`), so overlapping gates could fail for a reason
  unrelated to either feature and add interventions that measure
  nothing. A separate small PR (standard flow) moves the two paths under
  the script's `$workdir` and is merged before S1, so the clone has it
- D10 (records): the evidence file and the record slices are written by
  `implementer` seats of this plan from data files the director leaves
  in this session's scratchpad (the intervention log, the `jq` outputs,
  the token sums); the director writes no repository file during the
  trial
- D12 (snapshot): before S6 removes the clone, the director copies the
  ledger's records (`manifest.jsonl`, `inbox.jsonl`, `director.jsonl`,
  `escalations.jsonl`, the split plan, `director-wait.json`, the gate
  records, the feature plans' approval lines) and the seats' token sums
  into this session's scratchpad. S4 commits a sanitized copy of them
  under `docs/evidence/org-trial-2026-10-20/` (pane and workspace ids,
  session ids, and any random hex replaced by stable labels such as
  `pane-1`, so events still join; `$HOME` as `~`), and every table of
  the evidence is computed from that committed copy with the `jq`
  commands the evidence gives, so a reviewer can recompute them

## Risks and mitigations

- R1 dialogs block a seat (folder trust in a new worktree, the bypass
  consent): the director reads the pane with `ralph org read` first; it
  answers only the folder-trust dialog of the trial's own clone; any
  other dialog goes to the human. Answering a pane with a key is outside
  what the `/director` skill lets a director do ("ralph と gh の操作
  だけ"); the evidence records it as a trial-only deviation, and S5
  adds a finding row: nothing in spawn or start settles a new
  worktree's trust beforehand
- R2 cost or time runs away (a seat loops, a gate repeats): the director
  checks token sums every hour; past four hours from the first start, or
  a seat repeating the same failure three times, it reports to the human
  and stops the org on the human's word
- R3 a feature org fails or stops (BLOCKED, a leader that ends): the
  director reports it and records it as a finding; it does not implement
  the fix (the `/director` skill's "してはいけないこと")
- R4 real changes reach main: the two fixes are small, pass the gate
  and CI, and the human decides the first merge and the switch to
  `auto_merge`
- R5 a real `osascript` runs: before any start, a pane's
  `command -v osascript` must print `/tmp/ot/bin/osascript`, and the
  watch is started from a shell with the same PATH
- R6 the ruleset is not fixed by the merge step: D8's fallback; row 297
  stays open
- R7 the machine is slow with two gates and the test suites at once:
  the leaders run the gate in the background (template step 12); the
  director waits
- R8 this session's context is summarized during the trial: the
  director re-reads its registration (`/director` 昇格 5) and the
  scratchpad's `interventions.log` and `trial-notes.md`, which it keeps
  current
