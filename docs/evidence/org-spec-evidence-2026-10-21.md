# 機能ごとの org の仕様の印の根拠(2026-10-21)

この文書は、仕様 `docs/specs/2026-10-07-org-multi-org-director.md` の FR-1〜FR-11、非機能要件 5 つ、受け入れ条件 15 個に付ける印の根拠を、項目ごとに表にしたものである。計画は `docs/plans/active/2026-10-21-org-spec-complete.md`。FR-12 は 9 段目の記録の PR(#243)で `[x]` になっているので、この表には入れない。

印は計画の「印の規則」で決める。`[x]` は、項目の動きが merge 済みのコードにあってテストで確かめてあり、外の道具(herdr、codex、claude)に頼る項目はその道具で動かした実機の記録も 1 つあり、試行の所見のどれとも食い違わない項目に付ける。食い違うとは、項目の文が起きないと言っていることが試行で起きたか、項目の動きを起こすのに回り道が要ったことで、食い違う項目はほかの根拠がそろっていても `[ ]` にする。仕様の注が読み替えた項目と、部品ごとのテストで確かめた項目は、読み替えた形で満たし所見と食い違わなければ `[x]` にして、その注かテストを指す。それ以外は `[ ]` にして、足りないものと仕様の Open questions の問いを書く。9 段がすべて merge 済みであることは仕様の Status の節で言い、項目の印とは分ける。

確かめた版は、main の 765bcc46 を base にしたブランチ `docs/org-spec-complete` の 85ec1339 である(base との差は計画のファイル 1 つ)。書き方は次のとおり。

- 「試行」は `docs/evidence/org-trial-2026-10-20.md` を指し、そのあとに節の見出し(英語)を添える
- テストは「パス の 関数名」で書く。表のテストの関数名は、このブランチで `git grep -n 'func <名前>(' -- '*.go'` を打ち、どれも 1 件だけ見つかることを確かめた
- 仕様の注は、FR の番号と注の書き出し(「6 段目の後半で決めたこと」など)で指す。仕様の行番号は、次のスライスで Status の節を足すとずれるので書かない
- tech-debt の行は、`docs/tech-debt/README.md` の行を最初のセルの先頭の数語で指す。行番号は変わるので書かない
