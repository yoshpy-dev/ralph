3. Upgrade removal path smoke test (AC-5)
=====================================================================

Test: TestRunUpgrade_RemovesRetiredLoopArtifactsFromManifest
Location: internal/cli/upgrade_retired_loop_artifacts_test.go (a dedicated,
single-purpose file — see below for why it is not folded into cli_test.go)

Approach chosen: a Go test using the REAL embedded templates
(`github.com/yoshpy-dev/ralph`'s go:embed `TemplatesFS`, the same value
`cmd/ralph/main.go` injects at runtime) rather than the fstest.MapFS mock
used by the rest of internal/cli's tests. `executeInit` scaffolds a fresh
project against the actual current template set, then the test hand-adds
three manifest entries + matching on-disk files simulating artifacts a
pre-retirement `ralph` would have tracked (`scripts/ralph-orchestrator.sh`,
`scripts/ralph-pipeline.sh`, `.claude/skills/loop/SKILL.md` — all three
verified absent from the current `templates/base/` tree). Running the
current `ralph upgrade` (`runUpgradeIO`) against that manifest is asserted
to report all three as removed-from-template and drop their entries from
`.ralph/manifest.toml`.

This proves the removal path for real (against the actual shipped
templates, not a synthetic fixture), not just against a hand-picked mock.

IMPORTANT scope finding #1: `ralph upgrade`'s ActionRemove handling
(internal/cli/upgrade.go, `case upgrade.ActionRemove`) is notify-only by
design — it prints "review and delete manually" and drops the manifest
entry; it does NOT delete the file from disk. The test asserts this
explicitly (the three loop-artifact files are asserted to still exist on
disk after upgrade). This is a deliberate correction to this slice's
handoff wording ("prove upgrade removes retired loop artifacts from disk"):
the actual, current contract is manifest-level retirement + a user-facing
notice, not silent disk deletion — a safety property, not a gap. The test
name and doc comment reflect the real contract rather than the handoff's
more aggressive phrasing.

IMPORTANT scope finding #2: the test necessarily names the retired
artifacts' historical filenames ("ralph-orchestrator", "ralph-pipeline") as
literal fixture strings, which trips `tests/test-no-loop-references.sh`'s
guard (AC-2, closed by Slice 2 of this same plan) — that guard greps for
those exact substrings anywhere in `.go` files. Rather than touch Slice 2's
already-closed PATTERN/EXCLUDE_REGEX widening work, the new test was placed
in its own dedicated file (not folded into the much larger cli_test.go) and
that one file was added to EXCLUDE_REGEX, mirroring the exact precedent
already set for internal/cli/insights_test.go (a test that also legitimately
names retired vocabulary as proof of retirement, not as a live reference).
This keeps the exclusion's blast radius to one small, single-purpose file
instead of exempting all of cli_test.go's ~2300 unrelated lines from the
guard. `./scripts/run-verify.sh` passes with this change; `tests/test-
no-loop-references.sh` run standalone also passes.
