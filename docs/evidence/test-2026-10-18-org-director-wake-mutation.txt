## Equivalence notes

- O3 (the said-once key without the reason): for a ledger ralph writes, the reason a registration is skipped does not change while its id stays the same. A registration's launch, wake, wake_cmd presence, and pane are fixed at attach or start; a different reason needs a new id (attach --replace, start). Only a hand-edited director.jsonl (for example the same id changed from a herdr launch to a promoted session) changes the reason under one id, and then the second reason is not said. Judged equivalent for ralph-written ledgers; LOW at most.
- G5 (recordSuccess removed): recordSuccess deletes the failure time of a registration. A wake is only sent when holdsBack is false, which already means no failure in the last 5 minutes, so a stale entry left behind only holds back again if a new failure is recorded, which overwrites it. Expected equivalent; its red run came only from the flake below, and the kill matrix keeps it green.

## Flake

- `TestWakeDirector_AFailedWakeIsNotTriedAgainForFiveMinutes/no_return_in_time` (internal/org/director_wake_test.go:952, "woken [] after 0 runs, want none after one"). The row sets DriverCallTimeout to 1 s; the stand-in script records its run before `exec sleep 30`, and under load the sh start and the mark write do not happen within 1 s, so the run is killed before it is recorded.
- Seen in the A3, C2, G5 and G6 mutant runs (none of them touches timing) and in 1 of 40 runs of `-count=40` at HEAD with load average 15 to 240 from other sessions. A3, C2 and G6 were also red through other tests; G5 was red only through this subtest.
- Proposed fix: raise the row's timeout to about 3 s, or accept `len(runs) <= 1` for the timeout row.
