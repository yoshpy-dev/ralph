## Positive notes

- **AR-3 is fixed at the deciding site, not beside it.** `codexSpawnCorrelation` reads only `EventSpawnStarted` / `EventSpawnStep` and skips `DryRun`, so a `rejected` state event cannot displace the launching spawn under any input; `Stop`'s codex-ness gate, the receipt's `CommandedModel`/`Driver`/`Role`, and the comparison value all come from that one event now. The AC-1 test asserts the roster invariant (`seat.Model == "gpt-9-nonexistent"`) *before* asserting the fix, so it cannot pass for the wrong reason.
- **The "a completed pass keeps its result even if ctx expired at the very end" rule is implemented exactly.** There is no `ctx.Err()` check after the candidate loop (`codex_session.go:214-216`), and inside `scanRolloutRecord` both terminal branches — `decided()` and `readErr != nil` — return/break *before* the next top-of-loop check (`codex_session.go:477-490`), so a match completed on the last line of the last candidate is never thrown away. Pinned by `..._CtxExhaustedExactlyAsPassCompletes_FoundStillReturned`, which calibrates the exact call count and then asserts the budget really is exhausted.
- **No ctx error can reach a receipt reason or a manifest event.** `observeCodexSpawnReceipt` filters with `isCtxDoneErr` before assigning `lastErr`, and all three reasons are package constants; `observeStopModelReceipt` discards the observer's error outright (`verbs.go:932-934`). `isCtxDoneErr` is also the right predicate: `ctx.Err()` is `Canceled`/`DeadlineExceeded` even under `WithCancelCause`, `errors.Is` handles wrapping, and no local-filesystem read error wraps a context error.
- **`6b63b69` is a genuine improvement, not churn.** Before it, `lastErr` could only ever be set, so an early unreadable candidate made the final reason `codexReadErrorReason` forever, even after a later clean pass. The one-line widening makes the declaration's own first clause ("the LAST COMPLETED pass's own error (nil or genuine)") true. (M1 is about the *other* comment not having caught up, not about this change.)
- **Both nanosecond-budget tests discriminate**, confirmed by mutation: raising the budget to 2 s makes both fail, i.e. the fixtures really are findable and the tests are not passing on an empty directory. The `TimeoutMS: 1` test cannot take the wrong branch even if the parent had not yet expired when the observation started, because that test writes no fixture and `ctx.Err()` is consulted before `lastErr`.
- **No spin, and the poll's shape is unchanged.** `waitOrCtxDone(obsCtx, interval)` always waits the full interval unless `obsCtx` is done, so dropping the manual `remaining` clamp neither shortens nor lengthens the poll — `obsCtx.Done()` carries the same bound. With a tiny `CodexModelObserveInterval` the loop runs many passes, as it did before this PR; each pass is three `ReadDir`s plus the ModTime pre-filter.
- **The correlation test's new rows were checked for vacuity.** The added dry-run `spawn_started` is discriminating (the dry-run filter is what excludes it); the added `rejected` row is documentation rather than a discriminator under the current code (state events can never be selected by either loop), but it guards a plausible future widening of the first loop's filter. Worth keeping, worth knowing which is which.
- **`docs/tech-debt/README.md` is consistent in both directions**: the delta adds no row and invalidates none, and the pre-existing row about the codex session-record parser (line 134) is untouched and still true after the ctx threading.
- No secrets, no debug statements, no commented-out code, no `docs/plans/active/...` paths in shipped comments, and no credential-shaped strings introduced. `-race` is clean over all new tests.

## Answers to the requested judgment points

1. **Three-value return / token parity.** The `(receipt, observed, isCodexSpawn)` shape is acceptable — the two bools are independent (`isCodexSpawn` gates the *token*, `observed` gates the *append*) and the call site reads cleanly as nested `if`s. A struct would not add much at one call site; if it is ever reused, prefer splitting correlation (pure, testable) from observation (I/O) over a struct. Token parity: `model_observed=` is now emitted iff `!DryRun && isCodexSpawn`. Never for a dry-run (dry-run short-circuits, and `codexSpawnCorrelation` skips dry-run events anyway), never for a claude-launched seat, never for a seat with no real `spawn_started`. Two deliberate divergences from the old `seat.Driver == "codex"` gate: a seat whose only events are `rejected` no longer gets `model_observed=none` (documented as intended at `verbs.go:874-878`), and a failed second manifest read now suppresses the token (**not** documented — see L2).
2. **Double manifest read.** No harmful disagreement that I can construct: `findSeat`'s roster supplies `PaneID`/`AgmsgTeam`/`Role`/`Driver`/`Model` for the event, and the second read supplies only correlation. A concurrent `spawn` landing between the two would make Stop correlate the *new* spawn after having C-c'd the old pane — narrow, and narrow before this PR too. It is not worth removing for correctness; it *is* worth removing to delete the new claude-path cost and the token-suppression case (L2). A comment is the acceptable minimum.
3. **Roster vs correlated spawn elsewhere.** `grep`ed `seat.Model` / `seat.Driver` / `seat.Role` across `internal/org/`: the only remaining roster-derived codex-adjacent site is the `stopped` event itself (`verbs.go:687`) — L1. `spawn.go`'s other uses are `p.*` (the request being served) or `existing.*` in `compensateStale`, both correct. Nothing in PR #174's other code takes a commanded model from the roster. The `stopped` event is *pre-existing* behaviour and an explicit plan non-goal, so intended — but now inconsistent with the token on the same line, hence LOW rather than silence.
4. **ctx plumbing.** Every unbounded loop is covered: the date-directory loop, the entry loop, the candidate loop (via `scanRolloutRecord`'s before-open check) and the line loop. `os.ReadDir` returning a whole directory at once and `sort.Slice` are both uninterruptible, which the doc comment states honestly ("can overrun ctx's deadline by … one syscall (ReadDir/Lstat/Open)"). The sort is bounded by the entries of at most three directories and is not separately checkable; acceptable, though `codexRolloutCandidates`' comment listing "sorting" among the work the checks address reads as broader than what the checks do. `isCtxDoneErr` is the right test (see Positive notes). No ctx error leaks into a reason. The "completed pass wins" rule is implemented exactly, with no check after the last candidate and no check after the last line.
5. **Spawn poll.** `ctx.Err() != nil` is checked at the right moment and in the right priority: the parent is the outer bound, and `codexCutShortReason` is the less specific, safer claim when both are done. A parent cancelled a microsecond after the budget expired reporting "cut short" is acceptable; the only cost is that bullet 3's word "first" over-promises (folded into M1). No path spins: `waitOrCtxDone` always consumes the interval unless `obsCtx` is done. With a tiny interval and no record, the loop runs `budget / interval` passes, each three `ReadDir`s plus `Lstat`s — same cost as before this PR, and now genuinely bounded *within* a pass, which is the whole point of AR-4.
6. **Stop's `context.Background()` + the 8 s budget.** Sound: Stop has no ctx of its own (every other driver call in `Stop` uses `context.Background()` too), and reusing `codexModelObserveTimeout` avoids a second knob, as the plan decided. The operator-visible gap is real — `model-routing.md` says stop "looks once more" and nothing anywhere says that one look can take up to 8 s. That is documentation drift, so I am *not* filing it as a diff-quality finding; flagging it for `/sync-docs` instead.
7. **Tests.** `countingCtx` is a good seam and no test depends on an exact count in a way that a harmless refactor would break *for the wrong reason*: the three calibrated tests re-derive their budget from the real code, and the one hardcoded test (`n=3`) is robust to placement changes — too robust, which is exactly M2. Calibrating by calling the internals first is the right design; it is what makes `..._CtxDoneBeforeSecondCandidate_...` and `..._CtxExhaustedExactlyAsPassCompletes_...` self-maintaining. The 1 ns / `TimeoutMS: 1` Spawn tests are deterministic: go1.26's `WithDeadline` cancels synchronously for a non-positive duration, and the `TimeoutMS: 1` test has no fixture and no competing branch; 60 plain runs and 25 `-race` runs were clean. One nit worth knowing but not filing: `countingCtx` is not goroutine-safe (`calls++` and the `close(done)` are unguarded), which technically breaks `context.Context`'s "safe for simultaneous use" contract — harmless because all five users call it on the test goroutine, and `-race` is clean.
8. **History-narrating comments and finding ids.** Four new "previous version / as before" comments (L4) and three bare AR ids (L3). No `docs/plans/active/...` path reaches shipped code. The two "before the fix" mentions in `verbs_test.go` are appropriate where they are.
