## Security review

This slice set was weighted for security (a destructive command, a bash guard, hook wiring). Three targeted probes, all with a negative result:

1. **`pre_bash_guard.sh` payload extraction is genuinely fixed on both paths.** Ran the real hook against a real-shape payload (`{"tool_name":"Bash","tool_input":{"command":"sudo …"}}`) with jq present and with a minimal PATH containing only `cat`/`sed`/`tr`/`dirname`. Both emit `permissionDecision: deny`. The change uses `lib_json.sh`'s already-documented dotted-path support rather than introducing a new extraction mechanism.
2. **No deny-rule bypass via a crafted payload.** I attempted the obvious shadowing attack — a Bash command whose text embeds `", "command": "echo safe` so the sed fallback's greedy `.*` prefers a later, benign `"command"` key. It does not work: JSON encoding escapes the injected quotes (`\"command\"`), and the escaped closing quote breaks the fallback pattern's `"command"[[:space:]]*:` requirement, so sed backtracks to the real key and still sees `sudo`. The jq path parses properly and is unaffected. Verified against the real hook, not by reading.
3. **No deny/ask pattern was weakened.** The `case` arms in `pre_bash_guard.sh` are untouched; only the extraction argument changed. Root and `templates/base/` copies are byte-identical (`cmp` clean), as are the two `.codex/config.toml` copies.

Residual (not filed as a finding, since it is pre-existing and out of this diff's scope): the guard fails open whenever extraction yields an empty string — which is how the row-100 defect stayed invisible for so long. If a future payload shape changes again, the failure mode is silence. A "no command extracted" diagnostic on stderr would make the next regression self-announcing.

`ralph adopt`'s destructive path is well ordered: git-clean precondition → preflight every target → print the full target list → confirm → write → manifest commit barrier. The clean-tree requirement is checked before anything is printed or written, so the documented "git is the only rollback" guarantee holds. The residual partial-write window (files written, manifest not) is documented in the error text and is git-recoverable by construction. M3 is about the test, not the implementation.
