## Notes for `/verify` (out of this review's scope, recorded so they are not lost)

Two places where the implementation and the plan text disagree. Judging them is spec compliance, so no severity is assigned here.

- The plan's Assumptions say the alias value's quotes are **not** stripped and matching is substring-based (`引用符…は剥がさず、部分文字列として判定する`). What shipped strips one layer of quotes and tokenizes on whitespace (`:131-138`). The tokenizing version is the better design — it is why `--models-dir` and `--m` do not false-positive — but the change is not in Deviation notes.
- The plan's Scope item 2 specifies the "alias present, no conflicting flag" Detail as `alias codex in <file> has no conflicting flags`; what ships is `no conflicting codex/claude alias in N scanned rc file(s) (M alias line(s) seen)`, which names no alias. The corresponding test asserts only the substring `alias line(s) seen`, so it does not pin either wording.

## Positive notes

- **No alias value ever reaches the output.** The Detail is built from `f.Name`, `displayPath(f.File)`, `f.Line`, and a fixed flag string (`:195`), never from the matched line. An rc file holding `alias claude='ANTHROPIC_API_KEY=sk-... claude --model fable'` produces `alias claude in ~/.zshrc:12 adds --model` and nothing else, so doctor output remains safe to paste into `docs/evidence/`. Home is collapsed to `~` (`:184-190`), matching the repo's redaction convention for committed evidence.
- **The check is read-only and process-free.** `os.Stat` + `os.Open` only; no shell is started, which is the plan's first non-goal and the reason the check stays deterministic. The candidate list is static, so the file set cannot be steered by repo content.
- **The exit-code claim holds where it matters.** `countFailed` counts `"fail"` only, `allPass` flips on `"fail"` only, and `--strict` elevates `checkScaffoldIntegrity` alone — so no rc file on any machine can make `ralph doctor` exit non-zero through this check. I checked this at the source rather than trusting the plan.
- **The herdr-absent downgrade is the right default and is implemented symmetrically.** Same Detail text, `info` instead of `warn`, plus one clause explaining why (`:205-206`), so the finding is still greppable in the output of a machine without herdr.
- **The two structural tests discriminate.** Remove the `seen` map and `TestCheckShellAliases_SymlinkedRc_DedupedToOneFinding` counts 2 instead of 1; remove the `ZDOTDIR` branch and `TestCheckShellAliases_Zdotdir_Detected` drops from warn to pass. `TestConflictingFlag`'s negative rows (`--models-dir`, `--m`, `-c a=b --effort xhigh`) pin the three near-miss spellings that the prefix rules could plausibly over-match, and the `-mgpt-5.5` row pins the concatenated form the Codex plan advisory contributed.
- **Fixture hygiene in the new tests.** Every filesystem-touching test goes through `setShellAliasTestHome`, which pins `HOME` **and** clears `ZDOTDIR`; the one test that needs an unresolvable home skips on Windows with the reason stated. No `t.Parallel()` anywhere in `internal/cli`, so the `t.Setenv` usage cannot race.
- **Mirror and template discipline.** All four `/org` skill copies and both recipe copies are byte-identical, and the added sentence names only shipped surfaces (`ralph doctor`, the check name, the recipe path) — nothing that would trip template purity.
- **Registration is minimal and numbering-stable.** One append plus a three-line comment; "8b" keeps every later check number unchanged, which is what the surrounding comments promised.
- **`checkShellAliases` is 63 lines including comments** — above the 50-line guidance in the global review rules, but linear with no nesting beyond two levels, so I am not filing it. If M2 adds the scanned-path list, extracting the Detail builder is the natural place to split.
