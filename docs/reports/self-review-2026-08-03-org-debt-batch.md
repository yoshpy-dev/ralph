## Positive notes

- **The AR-1 footgun is genuinely closed, not renamed.** `ManifestPathIn`/`ReceiptsPathIn` replace the root-relative constructors outright, and every production and test call site was converted in the same commit (`grep` for all four removed symbols returns zero hits repo-wide, `*.go` and `*.md` alike). The doc comments explain *why* the old shape was dangerous rather than just what the new one does.
- **The guard-completion slice chose the harder, more honest option.** Rather than keeping the file-wide `xreview-helpers.sh` exemption, it removed the exemption and made the file pass on its own merits — and the one new exclusion (`upgrade_retired_loop_artifacts_test.go`) is deliberately confined to a single-purpose file specifically so the exclusion stays narrow, with the reasoning recorded both in the guard's header and in the test file itself. That is the correct instinct for a guard whose historical failure mode was over-broad exclusions.
- **The upgrade smoke test corrects the handoff instead of satisfying it.** The handoff said "prove upgrade removes retired loop artifacts"; the implementer found `ActionRemove` is notify-only by design, asserted that real contract (manifest entry dropped, **file survives on disk**), and recorded the deviation in both the test doc comment and the evidence file. Using the real embedded `TemplatesFS` rather than the package's usual `fstest.MapFS` mock is the right call for a "does this work against what we actually ship" test.
- **The new watchdog tests target the mechanism, not the symptom.** `TestWatch_TotalBudgetCutoff_ResumeAfterAllSeatsStop_ReAlertsOnNewCutoff` goes out of its way (chmod-based Stop failure injection, out-of-band operator `Stop`) to reach `Active=true, Cutoff=false` so the `Active` fix and the `Cutoff` ratchet cannot be confused for one another, and its doc comment explains precisely why the pre-existing neighbouring test does *not* cover this case. `pruneEscalated`'s tests pin a deterministic survivor set rather than just a length.
- **The new tech-debt row is the right kind of honesty.** Slice 4 discovered that the `Cutoff` ratchet is org-scoped and never cleared — strictly outside its own scope — and registered it as a new row with its own trigger instead of quietly widening the fix or leaving it unrecorded. The row explicitly cites the `watch.go:635-637` comment that bounds the fix.
- **Evidence redaction was applied without being asked twice.** `docs/evidence/org-debt-batch-2026-08-03.txt` states its redaction convention up front and contains zero home-path or session-id leakage — the failure mode an open tech-debt row already tracks for two earlier evidence files.
