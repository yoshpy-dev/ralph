## Positive notes

- `scripts/ralph-cli-driver.sh` is the right shape for "small, boring, well-named abstraction" — 130 lines, single function `run_agent`, single dispatch on `$RALPH_LOOP_DRIVER`, two private helpers, no global state mutation beyond the documented sidecar files. The Codex branch even synthesises a Claude-shaped `<log>.json` so the rest of `ralph-pipeline.sh` is unchanged. The header comment block (lines 1-23) names every consumed global up-front, which is exactly the documentation `architecture.md` calls for.
- The `_codex_log` / `_has_codex` / "Running codex review..." drift that the prior cycle's self-review (`docs/reports/self-review-2026-05-07-codex-cli-parity.md`) flagged as the HIGH-severity finding is now fully resolved. Variables are `_xreview_log` / `_has_reviewer` / "Running cross-review (driver=…, reviewer=…)…", and the bookmark comment about issue #44 (which used to say "Loop is Claude-driven only at this point") is replaced with an accurate description of the contract. This is the right kind of follow-through.
- Three priority tests for `appendEnvIfMissing` (TOML-fills, env-wins, no-prefix-match) cover the three failure modes that would actually break the env > TOML > default contract. The prefix-match test in particular (`RALPH_LOOP_DRIVER_EXTRA=ignored` does not block adding `RALPH_LOOP_DRIVER`) is the kind of guard that catches the future bug where someone refactors to `strings.HasPrefix(e, key)` and drops the `=` separator.
- `tests/fixtures/cli-stubs/{claude,codex}` are deterministic — they record argv, cwd, stdin, and the value passed to `--output-last-message` to a JSON file the test can `jq` against. Crucially, the stubs are named exactly `claude` and `codex` so PATH lookup in the test harness exercises the *real* wrapper's shell-expansion and PATH resolution rather than mocking the wrapper itself. This is the right level of integration for a shell wrapper test.
- `validate_loop_driver` runs in `ralph-orchestrator.sh:55` (early, before any worktree spawn) AND in `run_preflight` (lines 239), so a typo in `RALPH_LOOP_DRIVER` cannot leak past the orchestrator and waste a slice. Defensive double-validation with negligible cost.
- `internal/config/config.go` mirrors the shell-side allowlist exactly (`claude|codex` / `read-only|workspace-write|danger-full-access` / `untrusted|on-failure|on-request|never`) and the test `TestLoad_LoopRejectsInvalidDriver` exercises all three rejection paths in one table. Cross-language enum drift (one of the patterns in this reviewer's memory) is actively prevented.
- Mirror discipline is clean: every `scripts/*.sh`, `templates/base/scripts/*.sh`, `.claude/skills/{loop,cross-review}/SKILL.md`, `templates/base/.claude/skills/...`, and `.agents/skills/...` pair I `cmp`'d is byte-identical. No drift introduced by this 2098-line PR.
- `internal/scaffold/embed_test.go:TestTemplateBaseRalphTomlHasLoopSection` is the right kind of test for an embedded-template change — it asserts the `[loop]` section with all four expected lines (header + driver + sandbox + approval) instead of just the header, which would have let a regression delete `codex_sandbox` silently.
- The fake-CLI integration test (`tests/test-ralph-cli-driver.sh`) exercises the cross-review dispatcher branches (Test 6) by running the real shell command the pipeline would run, not by mocking the case statement. This is the right contract for the reviewer-inversion AC because it would catch a regression where someone refactors the case-statement into an if-chain and drops one branch.
- `adversarial-claude.md` prompt explicitly says `--permission-mode plan` and "do NOT edit files, run network operations, or modify state outside of writing the triage report" — read-only-by-prompt is a defense in depth on top of the CLI flag, which matters because `--permission-mode plan` is a Claude-CLI-side enforcement and a maliciously-tampered prompt could try to escape it.

## Recommendation

- Merge: **MERGE** — no CRITICAL or HIGH findings. The pipeline must NOT stop before `/verify`.
- The MEDIUM findings are quality improvements, not blockers. The probe-rigor and `RALPH_CLAUDE_REVIEWER_MODEL` symmetry items are worth addressing in a small follow-up commit on this branch before merge if there is appetite, but neither blocks the Phase-2 deliverable. The unreachable-fallback in `pick_reviewer` is a code-smell-not-bug.
- Follow-ups (in order of value):
  1. Add `ClaudeReviewerModel` to `LoopConfig` and propagate via `appendEnvIfMissing` so the env > TOML > default contract is symmetric across all four Phase-2 knobs. Adds ~10 lines of code + 1 test.
  2. Restore the `--version` shape in Probe 1 and Probe 7 to catch broken-but-PATH'd binaries. Adds ~4 lines per probe.
  3. Surface `<log>.stderr` content in the codex-driver fallback warning so silent-failure debugging does not require manually opening sidecar files. Adds ~3 lines.
  4. Either remove the unreachable `pick_reviewer` third-arm or convert it to a hard error so a future caller that bypasses `validate_loop_driver` fails loudly.
  5. Sweep the LOW items opportunistically — `strings.HasPrefix` swap, dedup the two `contains` helpers, collapse `checkLoopDriver`'s switch arms, tighten the `templates/base/ralph.toml` priority comment. None blocking.
