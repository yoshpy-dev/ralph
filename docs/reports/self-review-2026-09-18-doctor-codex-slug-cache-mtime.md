The intended "Status values never change, info untouched" property is visible structurally, not just by assertion.
- **The rename-vs-in-place reasoning in the helper doc is correct.** An open descriptor keeps the unlinked inode alive, so a rename-based refresh leaves `before`/`after` agreeing and returns the old mtime alongside the old bytes — contents and timestamp stay on the same version, which is exactly what the clause promises. The conservative direction of the residual error (a rewrite that completes between the first Stat and the read reports `freshness unknown` even though the bytes were self-consistent) is the safe one.
