## Positive notes

- The 2-phase snapshot ordering is implemented exactly as the plan's Codex-finding-1 revision specifies, and the reasoning is written down at the point of use (`upgrade_v2.go:69-80,135-153`) rather than only in the plan. `TestRunUpgradeV2_SettingsWriteFailure_SnapshotNotAdvanced` injects the failure between the two phases and asserts both the non-advance and the successful retry.
- That test also avoids the root-CI trap that `chmod 0444` failure injection normally creates: it `t.Skip`s with an explicit message when the write unexpectedly succeeds, instead of failing on a container CI running as uid 0.
- A deleted `.claude/settings.json` does not brick the upgrade: `parseSettingsDoc` maps empty input to an empty object, so the merge recreates the file from the owned template rather than erroring on invalid JSON. Worth recording because the file is in `SkipPaths` and the planner therefore can never recreate it.
- Exit-code plumbing is correct end to end: `root.go` sets both `SilenceErrors` and `SilenceUsage`, so `main.go` is the sole printer and an exit-3 run does not dump cobra usage text on a successful-but-drifty upgrade.
- `rebuildManifestV2` carries fork, drift, legacy-skipped, and preserved entries over *before* the desired-state loop and marks them `handled`, which is what makes the plan's "classification stability across a resumed run" claim actually hold. The seed-owner branch reads final disk content instead of assuming the template hash — the one place where assuming would have been wrong.
- `ApplyOps`'s Lstat preflight runs as a separate full pass over `plan.Ops` before any write, so a single symlinked target aborts with zero writes rather than partway through.

### Accepted residue (not worth a fix on the final cycle)

- `os.RemoveAll(filepath.Join(absDir, cleanBaseline))` (`internal/cli/upgrade_v2.go:192`) is the one filesystem mutation in the v2 flow with no `ValidateRealParentChain` call, which looks like a missed site given the fix commit's title. It is not one. `os.RemoveAll` does not follow a symlink at the leaf — a symlinked `.ralph/baseline` is unlinked, not traversed — and a symlinked `.ralph` parent resolves to the same real directory the manifest itself was just read and written through, so removing `<real>/baseline` is the intended outcome rather than an escape. ### Positive notes on the delta

- `ValidateRealParentChain` fixes the right layer. The cycle-1 cross-review finding was about a leaf-only `Lstat` being blind to a symlinked *parent* with a missing leaf; the fix adds the check as a separate full pass over `plan.Ops` **before** the existing leaf pass and before any write, so `ApplyOps` keeps its all-or-nothing property. `TestApplyOps_ParentChainPreflightRejectsSymlinkedParent_ZeroWrites` proves this by ordering a would-succeed op ahead of the poisoned one and asserting it did not land.
- The four new `replaceplan_test.go` cases include both control cases — real nested directories, and entirely missing intermediate directories — so the guard is pinned against over-rejection, not just under-rejection. Without the second control, an implementation that rejected every `os.ErrNotExist` component would pass.
- Each of the three new symlink tests fails on the pre-fix code by construction: pre-fix, `os.WriteFile` follows the symlink and the assertion on the external target's content (or the external directory's emptiness) is what breaks. These measure the code, not the harness.
- The `ApplyOps` doc comment was rewritten in the same commit that changed its behaviour, and the new text distinguishes the two checks and states *why* the leaf check alone is insufficient. The header comment and the body comments agree with each other and with the code.
- `WriteUpgradeReport` got the same treatment as the cli-side exception faces rather than being left as the odd one out, and its doc comment says explicitly that it bypasses `ApplyOps` and why.
- The M5 fix deleted the unreachable members instead of documenting them into permanence, and removed the tests that existed only to cover them — the register did not gain a row for code that no longer exists.
