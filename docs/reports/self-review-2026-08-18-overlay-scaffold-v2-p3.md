## Positive notes

- The 2-phase snapshot ordering is implemented exactly as the plan's Codex-finding-1 revision specifies, and the reasoning is written down at the point of use (`upgrade_v2.go:69-80,135-153`) rather than only in the plan. `TestRunUpgradeV2_SettingsWriteFailure_SnapshotNotAdvanced` injects the failure between the two phases and asserts both the non-advance and the successful retry.
- That test also avoids the root-CI trap that `chmod 0444` failure injection normally creates: it `t.Skip`s with an explicit message when the write unexpectedly succeeds, instead of failing on a container CI running as uid 0.
- A deleted `.claude/settings.json` does not brick the upgrade: `parseSettingsDoc` maps empty input to an empty object, so the merge recreates the file from the owned template rather than erroring on invalid JSON. Worth recording because the file is in `SkipPaths` and the planner therefore can never recreate it.
- Exit-code plumbing is correct end to end: `root.go` sets both `SilenceErrors` and `SilenceUsage`, so `main.go` is the sole printer and an exit-3 run does not dump cobra usage text on a successful-but-drifty upgrade.
- `rebuildManifestV2` carries fork, drift, legacy-skipped, and preserved entries over *before* the desired-state loop and marks them `handled`, which is what makes the plan's "classification stability across a resumed run" claim actually hold. The seed-owner branch reads final disk content instead of assuming the template hash — the one place where assuming would have been wrong.
- `ApplyOps`'s Lstat preflight runs as a separate full pass over `plan.Ops` before any write, so a single symlinked target aborts with zero writes rather than partway through.
