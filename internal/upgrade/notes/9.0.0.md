- Once `ralph upgrade` replaces `scripts/run-verify.sh` and `scripts/detect-changed-languages.sh`, a repository with no language pack, no `scripts/verify.local.sh`, and no `.ralph/local/verify.d/` or `test.d/` drop-in gets exit 2 from `run-verify.sh` for a change that touches code: in CI, locally, and in `ralph org gate` and a `ralph org regate` that runs the scripts (not under `regate_checks = "ci"`), which then record a failed gate. Before, the full scope (the default of `run-verify.sh`, which CI and the gate use) looked only at staged and unstaged changes, so a clean checkout passed such a change as docs only. This is why the release is 9.0.0. A change of only docs (`*.md`, `docs/`, `.harness/`) and ralph scaffold files (`.ralph/manifest.toml`, the paths it lists, `.ralph/baseline/`) still passes, and a file under `.claude/` that is not `.md` and not in the manifest now counts as code. To pass, add an executable `scripts/verify.local.sh`, an executable `.ralph/local/verify.d/<name>.sh` (`test.d/` for the test mode), or a language pack with `ralph pack add <language>`; the exit-2 output names an example path and these options.
- `scripts/detect-changed-languages.sh` now reads the change set against the merge-base with the base in both scopes, and takes the base from `GITHUB_BASE_REF` first, so CI uses the pull request's base and the seed `.github/workflows/verify.yml` needs no change. When the change set cannot be read (no ref for the base, no merge-base, a failed listing, such as a shallow checkout without the base branch) and no verifier runs, `run-verify.sh` exits 2 with the reason instead of passing; the seed `verify.yml` checks out with `fetch-depth: 0`, and a workflow of yours that runs `run-verify.sh` needs the base branch fetched too. A local shell that still exports `GITHUB_BASE_REF` now moves run-verify's base too.
- The leader, reviewer, implementer, and director role prompts changed. They are built into the `ralph` binary and written when a seat starts, so a running org keeps the old text until its seats start again: `ralph org reseat` restarts every seat of a feature org, `ralph org start --plan` restarts only a stopped leader, and a headless director needs `ralph org director stop` and then `start`. The watch's new readings below (`result_missing`, more usage limit screens) run only in a watch started by the new binary: stop a running one with `ralph org watch --stop` and start it again with `ralph org watch --all --detach`. The upgraded `/org` and `/director` skills use flags this release adds (`--issue`, `--requeue`, `--restart-herdr`, `--without-decision`), so everyone who runs them needs ralph 9.0.0.
- `ralph.toml` is a seed file: `ralph upgrade` shows the template's change to it under Advisories, as a diff against your copy, and does not edit it. The one new key, `[org.permissions].codex_network_access`, loads as `true` when absent; the rest of the change rewrites comments (`[verify].base`, `[reviewer]`, `[org.director].auto_merge`, `[org.review]`).
- Codex seats in `autonomous` and `edits` mode (allowed while `[org.permissions].codex_verified` is true) can now reach the network by default: ralph passes `-c sandbox_workspace_write.network_access=true`, and `codex_network_access = false` passes `=false` instead. That such a `-c` value wins over your `~/.codex/config.toml` was checked once, with `codex sandbox` on codex-cli 0.166.0, not inside a seat. Guarded codex seats and claude seats are unchanged, and `ralph doctor` adds a "Codex sandbox (seat network)" check (info when true, warn when false); `.codex/README.md` describes the flag. A seat's flags are fixed when it starts, so a running seat keeps the old ones until it starts again.
- `ralph org inbox resolve` now refuses, with nothing written, to close a plan's QUESTION whose approval `ralph org approve` recorded until the approval DECISION has been sent to the leader with `ralph org send`; `--without-decision` closes it anyway. To check this, `ralph org send` records a `text_sha256` of the whole message on each `sent` event, so a DECISION sent by an earlier ralph does not count, and such an item needs `--without-decision`. The `/director` and `/org` skills send the DECISION before the resolve, and a leader waiting for approval reads the item with `ralph org inbox show` when woken and goes on once it is resolved with the `approved <PLAN>` note.
- A human's decision about a running feature org that answers no inbox item can now go to the leader as a DECISION whose line after `TYPE: DECISION` is `ORIGIN: human` (agent-messaging rule, "A human's decision"). The `sent` event of a real send keeps its whole text, and a leader started again with `ralph org reseat` or a `start --plan` restart finds these decisions in full in its task and carries them out. `ralph org send` refuses any other `ORIGIN` header and such a message over 16 KiB, records the decision only when the send exits 0, and prints its own note when such a send fails; the `/director` skill (人の決定を送る) and the director role prompt never press Enter by hand to recover one.
- A split plan's header may now carry one `- Shared: <path>, ...` line for paths every feature may change (a lockfile, a root config): the watch does not count changes to them as outside the reservation, the leader's task gets a `- 共有のパス:` line, and seats get those paths in `--scope`. A shared path may not overlap another running org's reservation: `ralph org start --plan` and `ralph org spawn --reserve` refuse whichever of the two starts second, while two orgs may share a path. A split plan whose header already had a line starting with `- Shared:`, or that has one at the start of a line after the header outside a code block, now reads it as this field and can fail to load. The `/org` skill adds how to fix a conflict on a shared path.
- New `ralph org start --plan ... --issue <number>`: the org's leader writes `Closes #<number>` in its PR body, so merging the PR closes the issue the feature was filed as. The number is recorded with the feature binding, shown as `issue:` in `ralph org status` and as `binding.issue` in `ralph org merge-order --json`, and kept by `ralph org reseat`; starting an org that was not disbanded again needs the `--issue` it was started with, or none when it had none. The `/director` skill starts a filed feature with it and checks after the merge that the issue closed.
- In a feature org, the reviewer seat now runs the cross-review itself on its own driver and model and calls no other CLI (`codex exec`, `claude -p`), whether or not the implementer uses the same model family; `[reviewer]` no longer applies to it (model-routing rule). For a reviewer of the other family, set `[org.role_models].reviewer` to the driver the implementer does not use. The leader's cross-review TASK now carries only `XREVIEW_BASE:`, `CYCLE:`, and `REPORT:`, and a reviewer seat started by an earlier ralph answers it with a QUESTION, so restart an org's seats together with `ralph org reseat`.
- Implementer and reviewer seats now send their RESULT, BLOCKED, and QUESTION with agmsg's `send.sh` in a fixed form and check each send: after a non-zero exit they send once more, after an exit 0 they look for the line in their agmsg history, and when the second send fails or the line is not there they write `SEND FAILED: <TYPE> <TASK_ID> <file>: <reason>` on their screen and stop. The watch adds the seat condition `result_missing`: when a seat other than the leader waits for input for `[org.watchdog].stall_minutes` with no RESULT or REVIEW for its last TASK in its history, it sends the leader an `ALERT` naming the seat and the `TASK_ID`, and holds that seat's stall meanwhile, so a seat that sits idle after its RESULT gets its stall up to `stall_minutes` later than before. The leader role prompt reads the seat's screen and asks it with a DECISION to send again; the agent-messaging rule and the `/org` and `/director` skills describe both.
- The watch counts more claude seats in the org condition `usage_limited` instead of raising a stall: a seat that retries inside its turn after a usage limit (a `Retrying in ... · attempt n/m` status line right above the input box with the same reset time as the turn's limit sentence, as seen at the weekly limit), and a seat whose limit sentence is on the last `⎿` result line under a tool call or notice head such as `Ran 1 shell command`, `Read 2 files`, `⏺ Bash(...)`, `⏺ Monitor "..."`, or `⏺ Background command "..."`. The agent-messaging rule lists these screens.
- `ralph org resume` reads the same claude screens: a limit sentence on such a `⎿` result line is read as stopped, so resume types its continue text there. A seat that waits for a limit to reset gets the reason `waiting for the usage limit to reset: <line>`, also when herdr reports it working, and resume still types nothing into it. A column-1 `⏺ API Error` right under the prompt is now read as stopped (it was unknown), and a reply that quotes one limit or API error line under its own head is now unknown (it was stopped).
- `ralph org merge` now works on a default branch with a GitHub merge queue and at least one required status check (it refused before, and still refuses with no required check): it adds the PR to the queue at the gate's head, waits within `--wait-checks`, and records `pr_merged` with `via=merge_queue`. It exits 7 when the wait runs out with the PR still in the queue (run it again to keep waiting), and refuses a PR removed from the queue after its latest gate record unless you pass the new `--requeue`. This path has been tested only against a fake `gh`, not a real merge queue.
- In a repository with a merge queue, `ralph org merge-order` lists a branch whose gate base is only behind the default branch as `ready` (or `accepted`) instead of `rebase`, and `ralph org merge` adds it to the queue without a regate. merge-order prints a `merge queue:` line (`merge_queue` in `--json`) when the default branch has a queue, and `merge queue: unknown (<reason>)` with a note when the queue cannot be read (origin is not a GitHub repository, no `gh`), keeping `rebase` then. With `[org.director].auto_merge = true`, the `/director` skill merges in two steps there: it adds every ready branch with `--wait-checks 0`, then waits for each with `--wait-checks 60m`, and runs `ralph org cleanup` for a branch the queue merged first.
- New `ralph org reseat --restart-herdr` moves a feature org's seats to another account: after stopping the seats it stops the herdr server, starts it again with the command's environment, and then starts the seats; `--claude-config-dir <dir>` sets that server's `CLAUDE_CONFIG_DIR` (`''` removes it) whenever reseat starts the server. `--restart-herdr` must take every active seat of the org, and is refused, with nothing stopped, from a herdr pane (`HERDR_PANE_ID`, so a headless director in herdr cannot run it), when the server is not running, or when it holds any pane besides the org's active seats; stopping the server also closes an attached herdr TUI. Every reseat now prints the running server's `herdr server: CLAUDE_CONFIG_DIR=<value>` on stderr, with a `note:` when it differs from the value the seats should get. The `/director` skill runs `--restart-herdr` only when the human asks to move the seats to another account, and still never runs `herdr server stop` itself.
- The `/director` skill now makes a feature filed as an issue wait for the branches of its `- Depends on:` features too, not only for the running orgs whose reservations overlap it, including the `<Type>/<slug>` branch of a dependency that has not started yet. It counts a dependency as merged only when merge-order shows that branch `merged` with a binding of this split plan's feature or of the issue it was filed as, and a PR merged no earlier than that binding. It reads the issue number from the `issue:` line of `ralph org status` and the `binding.issue` of `ralph org merge-order --json`, which this release adds, and a running director follows the change once it reads the skill again.
- When `ralph org wait --inbox` with `--types` (with or without `--director`) times out, the message now ends with the open items of the TYPEs it did not count, such as `(counted only QUESTION,BLOCKED,RESULT; open items of other TYPEs: e144 ALERT)`, up to five; its start and the exit code are unchanged. The `/director` skill runs one inbox wait at a time, and when a wait prints that another wait took over, it starts no new wait and does not stop the older wait's Monitor.
- When origin is an SSH host alias (a `Host` in `~/.ssh/config`), `ralph doctor`'s Merge guarantee, `ralph org merge`, `ralph org cleanup`, `ralph org merge-order`'s read of the merge queue, and a regate under `regate_checks = "ci"` now resolve the real host with `ssh -G`, as `gh` does, before they call `gh`; when it cannot be resolved and `gh` fails, they say to point origin at the real host and pick the key with `git config core.sshCommand`. The merge guarantee cache adds `api_host`, and `ralph status` still matches origin by the alias. `ralph doctor` now stops on Ctrl-C during the Merge guarantee check with an `Interrupted:` line and exit 1.
- `ralph doctor`'s "Shell aliases (codex/claude)" check now reports an alias guarded by `HERDR_PANE_ID` as info, not warn, since a herdr pane does not define it: one alias right after `[[ -n $HERDR_PANE_ID ]] ||` (or a `-z` test followed by `&&`), or inside an `if` on that test alone. The `/org` skill shows this form as a way to keep a codex or claude alias out of seat panes.
- New `ralph pack remove <language> [--dry-run]` removes an installed language pack: it deletes the pack's files that are still as ralph wrote them, keeps and names the ones you changed or ejected (and symlinks and directories), and drops the pack and its entries from `.ralph/manifest.toml`, so `ralph doctor --strict` passes and `ralph upgrade` does not bring the pack back. Delete or move the kept files before you run `ralph pack add` for that language again: add overwrites a kept file, writes through a kept symlink, and fails on a kept directory. Every command that writes `.ralph/manifest.toml` now writes a temporary file and renames it over the manifest, so a symlinked manifest becomes a regular file with mode 0644.
- `ralph org gate` and `ralph org regate` now drop `GITHUB_BASE_REF` from the caller's environment before they run the scripts, as they drop `RALPH_VERIFY_*`. A gate that waits for `gate.lock` now keeps naming the gate that holds it in its stderr lines and log header while that gate releases the lock, instead of `a gate whose marker is not written yet`.
