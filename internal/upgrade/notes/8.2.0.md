- The leader, reviewer, and director role prompts changed. They are built into the `ralph` binary and written when a seat starts, so a running org keeps the old text until its seats start again: `ralph org reseat` restarts every seat of a feature org, `ralph org start --plan` restarts only a stopped leader, and a headless director needs `ralph org director stop` and then `start`.
- `ralph.toml` is a seed file: `ralph upgrade` shows the template's change to it under Advisories, as a diff against your copy, and does not edit it. The new keys `[org.watchdog].alert_notify` and `[org.gate].max_load` keep their defaults (`"batch"` and `0`) until you set them.
- New `ralph org reseat` in the `/org` and `/director` skills: it stops and starts a feature org's seats without a disband, for example after a usage limit or an account switch. After a reseat or a `start --plan` restart, the leader's task ends with a progress section built from the ledger, the inbox, and the branch's commits, and the leader role prompt skips a step that section shows as done only when it can check that the step is done.
- The watch raises the org condition `usage_limited` (one `ALERT` item per org, `REASON: usage_limit`, with a `SEATS` header) when seats stop on a usage limit or wait for one to reset, claude's 5-hour limit included. The `/director` skill tells the human and runs `ralph org resume` or `ralph org reseat` only when the human asks.
- The watch raises fewer alerts. While an `ALERT` item for the same org, seat, and condition is open or acked, a re-firing becomes a `recurred` event with a count on that item (`ralph org inbox show` prints it) instead of a new item. It raises no leader stall while the org has an open or acked QUESTION, BLOCKED, or RESULT, or while another seat is working. In an org with a reservation it raises `scope_change` only for paths outside the reservation. The skills and the agent-messaging rule describe these, and the `/director` skill reads an item with `recurred:` as one ongoing problem.
- The watch batches its desktop notifications for the `ALERT` items it sends, one per sending step (`[org.watchdog].alert_notify`; `"off"` sends none). New `ralph org wait --inbox --types <list>`: the `/director` skill still waits on every type, and uses `--types QUESTION,BLOCKED,RESULT` only when the human says to leave `ALERT` items to their ack deadline.
- New `ralph org gate accept`: the `/director` skill records a branch's latest gate failure as accepted only when the human explicitly accepts it, never for `head_moved`, `tree_changed`, or a failure caused by a tool version. `ralph org merge-order` lists the branch as `accepted`, and with `[org.director].auto_merge = true` (the default) the director merges an `accepted` branch with `ralph org merge` without asking, as it merges a `ready` one.
- The gates of one ledger now run their scripts one at a time, and when `[org.gate].max_load` is above 0 a gate waits up to 30 minutes while the 1-minute load average is above it. `ralph org gate` now also prints `LOAD:` and `TOOLS:` lines (the load average, and the node, package manager, python3, and go versions measured before the scripts). The reviewer role prompt counts the waits in a gate's time and copies both lines into the BLOCKED of a failed gate.
- `ralph org send` now types a message to a claude or codex seat as one bracketed paste and refuses a message that contains a paste marker. For those seats, when herdr still reports neither idle nor done near the end of `--timeout-ms`, it reads the screen and types only into a screen waiting for input (`--no-screen-fallback` turns this off). The `/org` skill adds `ralph org status --live`.
- The agent-messaging rule adds "How send types a message": after a send that failed while typing, the seat's input box may hold a paste placeholder or part of the text, clearing it is the human's step (one Ctrl+C), and leaders and directors only report it. A send can now also end `(text typed but not submitted)` when the screen check before Enter fails: a leader does not send it again and raises a BLOCKED, and a director presses Enter only when its whole DECISION is in the leader's input box.
- The `/director` skill and the director role prompt now handle the scaffold version `note:` line (printed by `ralph status`, `ralph org start`, `ralph org reseat`, and `ralph org director attach` and `start`) and the codex hook trust `note:` line: tell the human once, never run `ralph upgrade` or change codex's config, and re-read the skill at the line's `<dir>` after the human upgrades.
- A leader that sees the codex hook trust line from `ralph org spawn` raises a QUESTION and keeps working. The director, or the human through the `/org` skill when there is no director, resolves it at once, and a later answer goes to the leader as a DECISION with a `HOOK_SEAT:` header, which the leader does not read as a plan approval or a cap answer.
- A stopped feature org (not disbanded) can now be restarted with `ralph org start --plan` after its split plan was re-approved with changes only to other features' sections, because the split plan keeps a digest per feature. A change to the preamble still refuses every feature's restart, and the `/org` skill now says to put cross-feature contracts in the preamble. An org started by an earlier ralph has no per-feature digest, so any change to the split plan still refuses its restart.
- `.codex/README.md` and `.codex/config.toml` describe the Codex hook trust check of `ralph doctor` and how codex keys a hook's approval: editing any part of a hook's declaration, or moving it, needs a new approval, and approving once in the main checkout covers its linked worktrees.
